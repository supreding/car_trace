园区车辆轨迹查询 + 识别流水线 —— 系统速查
================================================

一、查询服务（部署在现场 Windows 电脑，局域网内访问）
  启动方式    双击 启动查询服务.bat（start_server.ps1，默认监听 0.0.0.0:5000，
              可用 -Port / -Bind / -Db / -OpenApiToken 参数调整）
  查询页面    http://<部署机IP>:5000/          （标注工作台 /label）
  开放接口    http://<部署机IP>:5000/api/open/...
              token 由环境变量 OPEN_API_TOKEN 配置（未配置则整组接口停用）
  接口文档    app/API接口清单.md（第一节约可直接发给对接方）

二、识别流水线（Windows，需 NVIDIA GPU + Python 3.12）
  启动方式    双击 启动识别流水线.bat（start_pipeline.ps1）；手工跑用它即可
  定时调度    Windows 计划任务（任务计划程序）每 30 分钟自动触发一次本脚本，
              在部署机"任务计划程序"里查看/修改触发器
  全量流程    bash run_full_pipeline.sh（Linux）或逐库跑 run_reid_pipeline.ps1
  步骤        .venv-reid 环境与依赖校验 → 照片同步入库（自动发现 data/ 下新园区）
              + OCR 时间戳 → GPU 流水线（检测/裁剪/属性/车牌/FastReID，只处理
              新增/未处理的抓拍）→ 收尾：未关联货车归类 → 大门照片重归类
              → 共用大门去重 → 车辆重聚
  归类收尾单步失败只告警不阻断，可 --undo-loose-assign / --undo-dedup 撤销。

  新园区接入：照片放 data/<园区名>/<月份照片根>/<日期>/<订单号>/，跑一次流水线
  自动同步；页面园区下拉框自动出现，无需改配置。

  共用大门跨园区去重（多园区共用同一大门时必开）：上游会把同一张抓拍照片写进
  每个园区的目录树（文件名一致，新版命名末尾带唯一id），同一辆车被多个园区计入。
  流水线在重归类之后自动判重，规则分两类：
    - 新命名（末尾唯一id，如 出磅2026年11月5日08：15：59_2346200）：id 全等直接判
      同一事件；id 不同即同秒不同车，绝不合并；
    - 旧命名（无id，存量多数）：同 (阶段+拍摄秒) 只是疑似，必须文件字节一致
      （MD5）才判同一事件——不同车不可能字节相同，旧数据重跑零误杀；
      文件不在盘（归档已清理）无法确认时跳过。
  每组按证据强制仲裁唯一赢家（真实订单 > 车牌锚定 > 行程时间线 > 外观 > 时间就近
  > 编号），落败副本移入 data/重复抓拍隔离-<原园区>/...（每个原园区一个隔离园区，
  页面与开放接口不显示，文件共享里可按园区查看），全部写 gate_dedup_log 日志：
    python app/build_db.py --dedup-gate              # 试运行（只报告不动数据）
    python app/build_db.py --dedup-gate --apply      # 真正隔离
    python app/build_db.py --undo-dedup              # 全部撤销；--capture-id N 单张撤销
  阈值可环境变量覆盖：GATE_DEDUP_SIM_MARGIN（外观领先幅度，默认0.03）、
  GATE_DEDUP_TIME_MARGIN（时间就近差距秒数，默认300）、GATE_DEDUP_SEQ_MAX_HOURS
  （行程时间线窗口小时，默认12）。

三、数据布局
  app/granary.db        主库（单库多园区：山高荃银丰麦田库 + 农易行临泉辉煌库）
  data/<园区>/...       原始抓拍照片（按 月份照片根/日期/订单 分层）
  app/reid_crops*/      车辆裁剪图
  app/API接口清单.md    全部接口清单与字段口径
